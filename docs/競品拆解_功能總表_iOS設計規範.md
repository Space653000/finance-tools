## 一、三個 App 的實測拆解

### A｜簡單複利（綠色圖表 icon）

**它有什麼**

| 分頁 | 欄位 |
|---|---|
| 基本 | 初期本金、計息期數 (n)、收益率 (%)、計算按鈕 |
| 定期定額 | 初期本金、每月投資金額、投資期數（年／個月）、利率（年／月）、複利方式（年複利下拉）、計算按鈕 |
| 結果 | 總收益 / 最終金額 兩個大數字 + 逐期明細表（# / 收益 / 總額 / 收益率） |

**它具備而另外兩個 App 沒有的功能**

1. **複利頻率可選** — 年／半年／季／月／日複利。這在借貸與債券情境下差異很大,B 和 C 都固定死。
2. **單位切換** — 期數可切「年／個月」,利率可切「年／月」。這是很體貼的細節,減少使用者自己換算的心智負擔。
3. **逐期明細表** — 唯一提供逐期拆解的。想驗算的人需要這個。

**它的不足之處**

- 上方一整塊 App Store 廣告,佔掉約 15% 螢幕,而且是**在財務數字正上方**,信任感直接歸零
- 要按「計算」才有結果 → 無法快速試不同數字
- 零圖表。純表格
- 「* 從第二個月開始追加本金」這種時序規則用小字註記,而不是設計進介面
- iOS 預設元件直出,沒有設計

### B｜複利計算機（米色 % icon）★ 最強競品

**它有什麼** — 五個分頁

| 分頁 | 內容 |
|---|---|
| 投資複利 | 投資模式（單筆投入／定期定額／**混合模式**）、初始投資、每月投入、年化報酬率、**通膨率** |
| 財務自由 | FIRE 說明卡、每月支出、目前年齡、安全提領率（附完整名詞解釋卡） |
| 貸款試算 | 每月收入、房產價值、總資產、**有房貸／有信貸／有車貸 三個開關**、合計月付與合計月付比 |
| 退休規劃 | 年支出／月支出切換、年支出、退休年齡、預期壽命、安全提領率、退休後年化報酬 |
| 設定 | 方案／提醒／語言／顯示 四格總覽、新手教學（欄位怎麼填／數字怎麼看／預設值意義） |

**它做對的（值得參考的設計方向）**

1. **「約 48 萬」換算 chip** — 輸入框右側即時把 `480000` 翻成「約 48 萬」。這是整個競品群裡最聰明的一個設計,直接解決台灣人看長串數字會數錯位數的問題。**必抄。**
2. **即時計算** — 「計算結果會即時跟著設定更新」,不用按按鈕
3. **內嵌名詞解釋卡** — 安全提領率下方直接附一整段白話說明,而且誠實寫了「4% 常被當作長期參考值,但不保證適用所有市場情境」
4. **提示卡防呆** — 「總資產這裡建議填不含房產價值的其他資產,避免和上面的房產價值重複計算」。這是真的在替使用者著想
5. **三種貸款可同時計算** + 合計月付比 — 已經有多層負債的雛型
6. **有通膨率** — 三個 App 裡唯一算實質購買力的
7. **新手教學分三類**：欄位怎麼填／數字怎麼看／預設值意義。分類正確

**它的不足之處（也就是我們的機會）**

1. **五個分頁互不相通** ← **這是最關鍵的結構性缺陷,見第二節**
2. **零圖表** — 五個畫面全是表單,一張圖都沒有。這是「看不懂」的主因
3. **每個分頁頂端都有一塊佔 15% 螢幕的巨大標題卡**,重複五次,純浪費
4. **全畫面單一米色** — 顏色不承載任何意義。安全與危險長得一樣
5. **輸入框內是灰色 placeholder 而非實值** — 使用者分不清那是預設值還是自己填的
6. **看不到結果** — 截圖裡滾了半天都還在填欄位。結果被推到很下面

### C｜複利計算（藍色計算機 icon）

**它有什麼**

- 「計算總覽」清單頁：每筆存檔顯示 最終資產／最終利潤／報酬率
- 自動命名：「本金 0 元,每月 1 萬,年利 4%,投資 30 年」
- 建立／編輯 管理
- 使用者也可自訂名稱（截圖中有「880 萬 18 年」「重新計算 5」）

**它獨有的一項功能（而且很重要）**

**它是三個裡唯一有「儲存多個情境並列表比較」的。** 這正是使用者實際的行為 —— 沒有人只算一次。截圖裡那五筆存檔（每月 1 萬／1.5 萬／2 萬 的三連比較）就是活生生的證據：**使用者在手動做 A/B/C 比較,只是這個 App 沒有替他做。**

**它的不足之處**

- 頂部 App Store 橫幅廣告
- iOS 預設 TableView 直出,零設計
- 清單只能上下滾動比較,**無法並排**
- 自動命名很長,在小螢幕會折行
- 零圖表
- 「最終利潤 +91.003%」對三筆不同金額顯示幾乎相同的百分比 —— 數學上正確（同利率同年期下,獲利佔投入比例本來就相同）,但**這個數字放在這裡完全沒有資訊量**,反而誤導

## 二、最關鍵的發現：B 的五個分頁不講話

這是整份分析最重要的一段。

App B 有 投資複利、財務自由、貸款試算、退休規劃 四個計算器。但在真實人生裡,**這四件事是同一件事**：

- 你的房貸月付會吃掉你能定期定額的金額 → 影響複利
- 你的複利結果決定你的 FIRE 年齡 → 影響退休規劃
- 你的退休年齡決定房貸還完沒 → 影響現金流
- 你的質押維持率決定崩盤時會不會被迫賣股 → 摧毀前面所有計算

**App B 讓你分別算四次,然後在腦子裡自己合併。** 這正是你在第一則訊息裡說的「沒有一個統一介面來評估」。

### 我們的答案

> **不是五個計算器,是同一個模型的五個視角。**

底層只有一份 `Scenario`（第一份規劃書裡的四原語模型）。五個分頁只是五種鏡頭：

| 分頁 | 它在問什麼 | 讀取同一份 Scenario 的哪個切面 |
|---|---|---|
| 累積 | 我的錢會長成什麼樣 | 資產曲線 |
| 負債 | 我背了什麼,每月要繳多少 | 負債層 + 現金流 |
| 邊界 | 我離斷頭多遠 | 約束條件 + 壓力測試 |
| 自由 | 我幾歲可以不上班 | 資產 vs 支出的交叉點 |
| 情境 | 哪個方案我撐得住 | 多個 Scenario 並排 |

**在「負債」頁改一個利率,「自由」頁的 FIRE 年齡立刻跟著變。**

這一句話,就是我們超越所有競品的全部理由。不是功能更多,是結構不同。

## 四、iOS 設計規範

> 你的要求：用 App Store 上最高使用率 App 的介面／字體／排版。
> 那個答案就是 **Apple 自家 App 的設計語言（Human Interface Guidelines）**。

### 4.1 為什麼參考 Apple 健康 / 股市 / 錢包

| 參考對象 | 為什麼 |
|---|---|
| **健康 App** | 資訊結構與我們完全相同：大數字結論 → 圖表 → 往下鑽明細。這是最該抄的版型 |
| **股市 App** | 高密度數字但不亂、漲跌色處理、清單即比較 |
| **錢包 App** | 卡片堆疊隱喻 → 我們的「情境卡」可以沿用 |

這三個是 iPhone 上安裝率最高的一批 App（系統內建）。使用者的肌肉記憶已經在那裡,**照著做等於零學習成本**,而且審核最保險。

### 4.2 字體（這一節最容易做錯）

| 用途 | iOS | Android |
|---|---|---|
| 拉丁字母與數字 | **SF Pro**（系統字） | Roboto |
| 繁體中文 | **PingFang TC 蘋方-繁**（系統字） | Noto Sans CJK TC |

**三個必守規則**

1. **不要自己指定中文字體。** iOS 的 zh-Hant 系統字就是蘋方,自己塞其他字體只會讓 App 看起來不像原生。
2. **數字一律開等寬數字（tabular figures）。** 拖動滑桿時數字才不會左右跳動。
   - Flutter：`fontFeatures: [FontFeature.tabularFigures()]`
   - SwiftUI：`.monospacedDigit()`
3. **必須支援 Dynamic Type。** 財務 App 的使用者年齡偏大,放大字級是剛需。

**Flutter 實作建議**

```dart
// 不要硬指定 fontFamily,讓平台決定,再補 fallback
TextStyle(
  fontFamilyFallback: const ['PingFang TC', 'Heiti TC', 'Noto Sans CJK TC'],
  fontFeatures: const [FontFeature.tabularFigures()],
)
```

### 4.3 字級（iOS Dynamic Type 標準值）

| 角色 | 級數 | 字重 | 用在哪 |
|---|---|---|---|
| Large Title | 34 | Bold | 分頁主標題（滾動時收合成 inline） |
| Title 1 | 28 | Regular | — |
| Title 2 | 22 | Regular | 區塊標題 |
| Title 3 | 20 | Semibold | 卡片標題 |
| Headline | 17 | Semibold | 列表主要文字 |
| Body | 17 | Regular | 內文 |
| Callout | 16 | Regular | 說明文 |
| Subheadline | 15 | Regular | 次要資訊 |
| Footnote | 13 | Regular | 註記、免責聲明 |
| Caption 1 | 12 | Regular | 圖表軸標 |

**結果大數字例外**：40–48pt Bold + tabular figures + `-0.5` 字距。這是全 App 唯一超出標準字級的地方,因為它是主角。

### 4.4 排版

- 內容左右邊距 **16pt**
- 間距用 **8pt 網格**（8 / 16 / 24 / 32）
- 可點擊區域最小 **44 × 44pt**
- 列表用 **Inset Grouped**（圓角卡片式分組,設定與健康 App 的標準版型）
- 卡片圓角 **12–16**,用連續圓角（squircle）
- 導覽列用 **Large Title**,滾動時自動收合
- 分頁列最多 **5 個**（B 已經是 5 個,不能再多）

### 4.5 顏色

用**語意色**,不要硬編色碼 —— 這樣深淺色模式自動正確。

| 語意 | iOS 對應 |
|---|---|
| 主背景 | `systemGroupedBackground` |
| 卡片背景 | `secondarySystemGroupedBackground` |
| 主文字 | `label` |
| 次文字 | `secondaryLabel` |
| 分隔線 | `separator` |

**再疊上第一份簡報定義的三條色軌**（報酬軌／風險軌／品牌軌）。品牌強調色只用一個。

### 4.6 元件對照表

| 需求 | iOS 元件 |
|---|---|
| 投資模式切換 | Segmented Control（B 已在用,保留） |
| 假設條件表單 | Inset Grouped List |
| 「約 X 萬」 | 輸入框內的 trailing accessory chip |
| 名詞解釋 | Sheet with medium detent（半高彈窗） |
| 情境管理 | Swipe Actions + Context Menu |
| 結果圖表 | Swift Charts 風格（Flutter 用 fl_chart 做出相同視覺） |
| 進階選項 | Disclosure Group（可展開列） |

### 畫面 3：情境（清單 + 並排）

- 上半：情境卡清單（沿用錢包 App 的卡片堆疊視覺）

## 六、上架前的三個檢查點

1. **廣告：一則都不放。** A 和 C 的廣告就壓在財務數字正上方,這是它們最大的信任缺口,也是我們最便宜的勝場。
